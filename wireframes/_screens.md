# Wireframes — місток IA → каркаси (R1 «Додати документ» · R5 «Екстрена картка»)

**Це ще НЕ верстка.** Це замовлення для наступного кроку: **які екрани** і **які
реальні стани** треба намалювати. Розкладка, компоненти, копірайт — не тут.

**Скоуп:** будуємо **ОДИН flow за раз** (той самий цикл, що R1 — щоб потік
склеювався, а прогалини IA ловились до верстки). Готово: **R1 «Додати документ»** ·
**R5 «Екстрена картка»** · **R2 «Показати анамнез»** (ядро MVP замкнене) ·
**R3 «Ліки»** (секція в кінці — table-stakes). R4 — далі, окремо.

Джерела (нічого не вигадано — усе звірено):
- екрани й теги — [`../sitemap.md`](../sitemap.md) (Екрани · Навігація · чек-ліст станів · IA-борг);
- місце у потоці й стани — [`../flows.md`](../flows.md) (R1);
- job кожного екрана — [`../research/jtbd.md`](../research/jtbd.md) (MAIN / R1 = RELATED-job 1, сц.4).

**Стани НЕ вигадані** — усі 4 вже задані в flows.md (R1) і чек-лісті sitemap;
тут лише витягнуто, де кожен **реально** настає:
- **Порожній** — холодний старт: порожній дашборд / порожній список.
- **Помилка** — збій *локального* сховища при збереженні (durable-чернетка вже його ловить → «Повторити»).
- **Завантаження** — синк на сервер **фоном** (в т.ч. офлайн-черга).
- **Успіх** — лише де є окремий екран/поверхня «вийшло» (не ставимо автоматично всюди).

## Екрани R1-flow (по одному)

### 1. Онбординг нового користувача → ★ «Додай СЕБЕ» → перший self-профіль
- **Назва (sitemap):** `★ «Додай СЕБЕ» → перший self-профіль` (під «Онбординг нового користувача») · тег `(MAIN · анти-холодний-старт)`.
- **Job (jtbd):** **MAIN** — «мати всю медичну картину родини під рукою й діставати потрібне за секунди» → тут закладається **вісь-Профіль** (перший self-профіль); enabler сц.10 «не сплутати, чий запис».
- **Місце у flow (R1):** вузол `onb` «Онбординг: Додай СЕБЕ → self-профіль» — гілка `cold →|так (новий)|`, веде в `empty` (порожній дашборд).
- **Реальні стани:** жодного з 4 — це **вхід у холодний старт**, не носій станів. Онбординг — *ремедія* порожнього застосунку (sitemap чек-ліст: «Порожній дашборд… вирішує онбординг ★ додай себе»), а сам порожнього стану не має. Одноекранна форма.

### 2. Дашборд профілю — «важливе»
- **Назва (sitemap):** `Дашборд профілю — «важливе»` · тег `(MAIN)`.
- **Job (jtbd):** **MAIN** — домівка профілю: «важливе» (критичне + дії на сьогодні + останнє) і «діставати ключове за секунди». Гасить холодний старт.
- **Місце у flow (R1):** вузол `dash` «Дашборд профілю» (гілка `cold →|ні|`) **і** вузол `empty` «СТАН: порожній дашборд (холодний старт)» (після `onb`) → `cta {Що далі?}` → або `sheet`, або `churn` (пішов).
- **Реальні стани:** **Порожній ✓** — це і є головний порожній стан продукту (flows.md `empty`; sitemap чек-ліст «Порожній дашборд (холодний старт)» + «Дашборд із порожньою секцією»). Саме тут живе **adoption-тупик** (`churn` — «не зрозумів навіщо → пішов»), тому цей порожній екран — найдорожчий для дизайну.
- **Вимога до `dashboard-empty.html` (реалізовано; ціль оновлено під R5):** порожній **критичний** блок (алергії / хроніка / група крові ще не внесені) — це **НЕ просто «порожньо»**, а точка, де продукт **проактивно підштовхує внести критичне**. Обґрунтування: критичне живить **R5**, а порожня базова картка = тупик `deadempty` (flows.md R5). **Ціль «внести критичне» = спільний `edit-base-card.html`** (той самий екран, що закриває R5-`deadempty`). У `dashboard-empty.html` замінити `#` на `edit-base-card.html` (у КРОК 2 R5).

### 3. Швидке додавання — вибір типу (глобальний ➕)
- **Назва (sitemap):** `Швидке додавання — вибір типу (sheet, глобальний «+»)` · тег `(R1 · R3 · R4)`. У цьому flow працює як **R1**.
- **Job (jtbd):** **R1** (RELATED-job 1) — «зафіксувати вхідне, поки не загубив» (сц.4); глобальний вхід у додавання з будь-якого екрана.
- **Місце у flow (R1):** вузол `plus` «Тап ➕ (1)» → `sheet` «Швидке додавання — вибір типу» → `type {Який тип? (2)}` →|документ| `adddoc`.
- **Реальні стани:** жодного з 4 — це **stateless-роутер** (bottom-sheet із пресетами типів). Немає даних → немає порожнього; немає збереження/асинхронки → немає помилки/завантаження; веде далі → не «вийшло».

### 4. Додати документ (фото-перший потік)
- **Назва (sitemap):** `Додати документ (фото-перший потік)` · тег `(R1)` ← екзистенційний ризик №1.
- **Job (jtbd):** **R1** (RELATED-job 1) — «зафіксувати вхідне, поки не загубив» (сц.4: фото-перший вхід, автодата, тип/лікар опційно). Головний ризик продукту.
- **Місце у flow (R1):** `adddoc` «Додати документ — фото-перший» → `src {Фото/галерея?}` → `cam {Дозвіл?}` → `shot` «Знімок (3)» → `draft` (durable локальне сховище одразу) → `savecheck {записано?}`.
- **Реальні стани:** **Помилка ✓** — `savecheck →|ні (рідкісний збій сховища)|` `retry` «Помилка сховища — Повторити» (flows.md R1). Це єдиний з 4, що тут настає.
  - *Порожній —* : екран-ввід, порожнього стану не має.
  - *Завантаження —* : синк на сервер **фоном** (durable-чернетка), цей екран **не блокує**; стан «в черзі/синхронізується» показуємо на екрані №5.
  - *Успіх —* : «вийшло» матеріалізується як екран №5 (не тут). `ok` «Збережено ✓» — це транзит-підтвердження (тост) на шляху в перегляд.
  - *Гілка, не стан:* `cam →|ні| gal` (дозвіл на камеру відмовлено → з галереї/файл) — це graceful-фолбек, **не** екран-помилка.

### 5. Документ — перегляд
- **Назва (sitemap):** `Документ — перегляд` · тег `(R1 · R2)`. У цьому flow — **R1** (результат фіксації; тип/лікар можна дозаповнити).
- **Job (jtbd):** **R1** (RELATED-job 1) — вхідне надійно «покладено на місце» (сц.4); (перегляд також живить R2 — поза цим скоупом).
- **Місце у flow (R1):** вузол `view` «Документ — перегляд (тип/лікар можна дозаповнити)» — після `ok` «Збережено ✓ — дата=сьогодні, профіль=активний».
- **Реальні стани:** **Успіх ✓** + **Завантаження ✓**.
  - *Успіх ✓* — це і є поверхня «вийшло»: `ok → view` (щойно знятий документ, збережений і видимий). Окремого екрана «вийшло» немає — ним є цей перегляд.
  - *Завантаження ✓* — «синк фоном»: якщо офлайн/у черзі, документ прибуває сюди зі статусом «збережено локально · синхронізується/у черзі» (flows.md `queue → ok → view`). Тут «синк фоном» стає видимим користувачу.
  - *Порожній —* / *Помилка —* : сюди потрапляєш лише зі збереженим документом; збій сховища — вище (№4), а невдалий синк flows.md **не** робить помилкою — лише **пере-ставить у чергу** (`sync →|ні| queue`), тобто це стан «Завантаження», не «Помилка».
- **Under-flow — дозаповнити метадані (НЕ стан):** опційно дозаповнити **тип** (пікер-overlay §7, 6 пресетів — CLAUDE фіча 2) і **лікар/заклад** (інлайн текст); **авто-save** при виборі/закритті, без кнопки (durable-принцип). Гілка додана у [`../flows.md`](../flows.md) (R1). Це edit-взаємодія, **не 4-й стан** → трекається окремим рядком у «Під-потоках» нижче.

## Матриця: екрани × стани

`✓` = стан реально настає (з посиланням) · `—` = сценарій його не дає.

| Екран (sitemap) | Порожній | Помилка | Завантаження | Успіх |
|---|:--:|:--:|:--:|:--:|
| 1. Онбординг → ★ «Додай СЕБЕ» | — | — | — | — |
| 2. Дашборд профілю — «важливе» | **✓**¹ | — | — | — |
| 3. Швидке додавання — вибір типу (➕) | — | — | — | — |
| 4. Додати документ (фото-перший потік) | — | **✓**² | —³ | —⁴ |
| 5. Документ — перегляд | — | —⁵ | **✓**⁶ | **✓**⁷ |

**Посилання на джерело:**
1. flows.md `empty` «СТАН: порожній дашборд (холодний старт)» + sitemap чек-ліст «Порожній дашборд» / «Дашборд із порожньою секцією». Тут же adoption-тупик `churn`.
2. flows.md `savecheck →|ні| retry` «Помилка сховища — Повторити» (збій **локального** сховища; durable-чернетка його ловить).
3. Синк — **фоном** (durable-чернетка), не блокує цей екран → «Завантаження» surface на №5.
4. Успіх матеріалізується екраном №5; `ok` «Збережено ✓» тут — транзит-тост, не окремий екран.
5. Невдалий синк flows.md пере-ставить у чергу (`sync →|ні| queue`), не в помилку → це «Завантаження», не «Помилка».
6. flows.md `queue → ok → view`: статус «збережено локально · у черзі/синхронізується» (в т.ч. офлайн).
7. flows.md `ok «Збережено ✓» → view`: перегляд щойно збереженого = поверхня «вийшло» (окремого екрана «вийшло» немає).

**Що це каже верстці:** з 5 екранів **проєктованих станів потребують лише 3**:
- **Дашборд** → намалювати **порожній (холодний старт)** — найдорожчий (тут adoption-тупик);
- **Додати документ** → намалювати **помилку сховища** («Повторити»);
- **Документ — перегляд** → намалювати **успіх** (приземлення = збережено) + **завантаження** (синк-pending / офлайн).

Онбординг (ремедія холодного старту) і ➕-sheet (stateless-роутер) — **одностанові**,
станів із цих 4 не несуть.

## IA-борг, дотичний до R1 (з sitemap → тримати на очах під час верстки)

- ✅ **Втрата фото при save-error — полагоджено** (durable-чернетка): саме тому «Помилка» на №4 — це збій *локального* сховища з «Повторити», а не тиха втрата знімка.
- ⚠️ **Підрахунок тапів vs діаграма:** ціль R1 «≤3 тапи» (`➕(1) → Документ(2) → знімок(3)`) **не враховує** вузол `src {Фото чи з галереї?}` та `cam {Дозвіл?}` у flows.md. Під час верстки №4 звірити реальну кількість тапів із діаграмою (можливий шлях: «➕ одразу камерою, Документ=дефолт-тип» → 2 тапи).
- ⚠️ **Adoption-тупик холодного старту** (`churn`) — **відкрито**: порожній дашборд (№2) мусить дати причину додати перший запис, інакше користувач іде. Це найризикованіший стан у скоупі.
- ⛔ **Поза цим скоупом (не блокує R1-каркаси):** login-error + відновлення пароля; модель шер-лінка R2; member-picker R5 — фіксуються в sitemap «IA-борг», тут не проєктуються.

# R5 — ЕКСТРЕНА картка  *(ядро MVP; вузький потік — 1–2 екрани)*

## Екрани R5-flow

### Екстрена картка — перегляд
- **Назва (sitemap):** `Екстрена картка — перегляд` · тег `(R5)` · [secondary-доступ].
- **Job (jtbd):** **R5** (RELATED-job 5, сц.6) — «бути готовим до критичного моменту, навіть якщо мене нема поряд». Гарячий момент, **офлайн обов'язково**.
- **Місце у flow (R5):** вузли `offcache` / `online → card → show`. **Два входи** (обидва на присутньому розблокованому пристрої Координатора): `header` «Шапка → 🆘 Екстрене (1)» (у застосунку) · `offcache` «офлайн-ярлик home-screen, без логіну застосунку».
- **Реальні стани (не 4 шаблонні):**
  - **База / успіх ✓** — критичне показано: **алергії · хроніка · група крові · активні ліки · екстрені контакти** (flows.md `show`). Щасливий шлях = **1 тап**. **Вибір члена — перемикач ПРЯМО на картці** (дефолт = активний профіль; «не той? → перемкнути» тут же, не окремий крок — flows.md `Той член?`). Офлайн — **тихий індикатор «з кешу»**. *(Акцент критичного — розміром/вагою; колір — §8/tokens.)*
  - **Порожній / deadempty ✓** — базову картку **НЕ заповнено** → у кризі нема що показати (flows.md `deadempty` — **НАЙДОРОЖЧИЙ тупик**). Проактивно веде **«заповнити критичне» → `edit-base-card.html`** (спільний екран із `dashboard-empty`). *Нюанс:* заповнення = **профілактика** (щоб наступного разу було) — саму гостру кризу не рятує; тому критичне женемо внести ДО кризи (звідси проактивність обох empty).
  - **Помилка —** : у кризовому шляху немає мережевого запиту, що падає (картка локальна / з кешу).
  - **Завантаження —** : офлайн-first, миттєво — спінера в гарячий момент бути не може.

**Офлайн-кеш — ОБОВ'ЯЗКОВА ВЛАСТИВІСТЬ, не окремий стан.** Картка МУСИТЬ рендеритись
із service-worker кешу **без логіну застосунку** (flows.md `offcache`; CLAUDE §6) —
це серце обіцянки R5. Онлайн/офлайн — **той самий вміст**; відрізняється лише

# R2 — ПОКАЗАТИ анамнез лікарю  *(ядро MVP; замикає R1/R2/R5)*

Джерела: [`../sitemap.md`](../sitemap.md) (Екрани · ПРОЄКЦІЇ · Сутність №7),
[`../flows.md`](../flows.md) (R2), [`../research/jtbd.md`](../research/jtbd.md)
(R2 = RELATED-job 2, сц.2/3/8). Межі — [`../CLAUDE.md`](../CLAUDE.md) (не-медичний).

**Природа: R2 — ПРОЄКЦІЯ, не CRUD.** Анамнез-PDF нічого не зберігає — **компонує
наявні дані** (базова картка + активні ліки + документи + показники + візити) у
документ для лікаря. Екран **не має власних сутностей**, збирає чужі — тому й стани
інші: **немає «порожнього» у CRUD-сенсі** (нема власних даних, що «ще не додані»);
натомість є **«неповна картина»** (тонкі джерела) і **залежність від мережі**
(серверна генерація).

## Екрани R2-flow

### Анамнез-PDF — генерація + перегляд
- **Назва (sitemap):** `Анамнез-PDF — генерація + перегляд` · тег `(R2)`.
- **Job (jtbd):** **R2** (RELATED-job 2, сц.2/3/8) — «показати повну картину іншому за секунди». Момент цінності перед лікарем; часто офлайн / за кордоном (мова).
- **Місце у flow (R2):** `📤 Показати (1) → screen → scope → sections → net → gen → show`. Щасливий шлях = **2 тапи** (показ на екрані), +1 — віддати копію.
- **Реальні стани (не 4 шаблонні — з природи проєкції + серверної генерації):**
  - **База / успіх ✓** — згенерований анамнез, готовий **показати на екрані** лікарю й **віддати копію** (файл / друк — **без лінка**, рішення «б», див. нижче). Компонує базову картку + ліки + показники + візити + (опц.) документи.
  - **Завантаження ✓** — **серверна генерація** PDF (flows.md `gen`). На відміну від R5 (кризовий glance, спінер недопустимий) — тут **спінер доречний**: не гарячий момент, лікар поруч, кілька секунд — норма.
  - **Помилка генерації ✓** — сервер не зібрав/не віддав PDF (flows.md `generr`) → **Повторити / показати кешований**. Це помилка **генерації** (проєкція не склалась), **не** збереження — R2 нічого не зберігає.
  - **Неповна картина ✓** — джерела тонкі (новий профіль, мало записів) → анамнез генерується **з чесною позначкою «це не вся історія»** (flows.md `weak`). **Межа не-медичного (CLAUDE §4):** позначка **факту неповноти** («це не вся історія» / «внесено мало записів») ✓, **НЕ** оцінка («недостатньо для діагнозу» ✗, «повнота 40%» ✗). Це **не «порожній»** — проєкція завжди щось компонує; це її розріджений край.
  - **Офлайн без кешу ✓** — генерація серверна → офлайн і без кешованої копії повний анамнез **не зібрати** (flows.md, було `deadoff`). **НЕ глухий кут:** чесне обмеження + вихід — **критичне доступне офлайн через Екстрену картку (R5)**; повний анамнез — щойно з'явиться мережа. *(Гілку змінено у flows.md → `offlim`.)*
  - **Офлайн з кешем — ВЛАСТИВІСТЬ, не окрема сторінка:** якщо анамнез уже генерували, показуємо **кешовану копію** з тихим індикатором «офлайн · з кешу» (flows.md `cache→так`; jtbd сц.2). Той самий вміст, що база.
  - **Порожній (CRUD) — / Помилка збереження —** : н/д — R2 нічого не зберігає й не має власних даних.

## Обсяг + мова — ВИЗНАЧЕНО (не окремі стани)

- **Обсяг** («повний анамнез» vs «лише критичне») і **мова** (укр/англ) — це **under-flow конфіг** (панель вибору розділів / обсягу / мови на екрані анамнезу; flows.md `scope`/`sections`), **не** стани життєвого циклу.

- Файл (КРОК 2): `anamnesis-config` (панель-overlay) або інлайн на анамнезі — вирішимо на верстці.

## «Можна X без як» — майбутні `href="#"`-тупики (називаю ЗАРАЗ)

1. **ШЕР — ✅ РІШЕНО (варіант «б»): лише файл + друк, БЕЗ лінка.** Публічний лінк — навіть із токеном — єдине місце, де дані жили б **поза RLS-ізоляцією**; це суперечить **стрижню** продукту (приватність / автономність: RLS, non-E2EE лише заради відновлення, автономність від ЕСОЗ), а вигода мала (кабінет → екран/друк; віддалено → PDF-файл вкладенням). **Сц.8 «надіслати лінк» → зафіксоване обмеження** (як звузили R5), **не діра**. Джерело оновлено (flows.md `how` → файл/друк; гілка лінка → `nolink`).
2. **Обсяг / мова** — ✅ визначено вище (under-flow + дефолти), **не діра**.

  з'явиться мережа». Дзеркалить принцип R5-`deadempty` (тупик дістає вихід).

Розклад — **окремий екран-під-потік** `medication-schedule.html`, **ІНТЕРАКТИВНИЙ**: клік по радіо → показує поля обраного типу під ним, ховає інші (**progressive disclosure**; мінімальний інлайн-JS — свідомий виняток зі «статичних екранів», бо контрол справді динамічний і статика вводить в оману). *(research: Apple Health/Medisafe — частота окремим кроком; GOV.UK — поля під обраним радіо, багатопільні набори не inline у формі → окремий крок.)* Поля: Щодня → «разів/день» (select) + час; Певні дні → чипи днів + час; Курс → дата-від/дата-до + час; За потреби → без полів. «Час» повторюється — норма. Системні контроли (select/time/date), не текст. У `Додати/ред.` розклад — **рядок-підсумок + «Змінити»** → цей екран. **Поза MVP (CLAUDE §1 — не повний фарм-трекер):** «кожні N днів» / циклічний (21+7) — не робимо.
2. **НАГАДУВАННЯ push-fallback — класифіковано:** це **under-flow (конфіг нагадувань) + чесний fallback**, не окремий стан екрана й не тупик. Push недоступний (iOS PWA) → **локальне/email + видимий статус «push вимкнено»**. Закриває IA-борг «push-fallback» (дзеркалить R2-`offlim` / R5-`nodev` — обмеження з виходом).
3. **ЗВ'ЯЗОК прийом ↔ журнал ↔ inline — ✅ ЗАКРИТО (IA-борг R3):** прийом — **одна подія** {дата-час, статус}. Позначити можна **будь-де** (дашборд-inline / деталь / нагадування) — пишеться **та сама подія**; журнал, inline і статус деталі = **три види одного джерела** (durable + синк). Одне джерело правди, не три лічильники.
4. **МЕЖА — AVOID (свідомо НЕ переходимо):** стріки · **% прийому** · статистика дисципліни · гейміфікація · «ви пропустили X днів». Kartka показує **розклад + факт**; журнал = **сирі події**, без агрегатів-оцінок. Саме тут трекер спокушає стати «другим центром» — не йдемо (CLAUDE §1).

# R4 — АНАЛІЗИ: зрозуміти зміну показника в часі  *(table-stakes; сц.7 — динаміка, не окрема цифра)*

Джерела: [`../sitemap.md`](../sitemap.md) (Сутність №5 Показник + Екрани · чек-ліст станів · IA-борг R4),
[`../flows.md`](../flows.md) (R4 — **діаграму створено цим кроком**),
[`../research/jtbd.md`](../research/jtbd.md) (R4 = сц.7; O19 discoverability). Межа — [`../CLAUDE.md`](../CLAUDE.md) §4.

**Природа + МЕЖА (найтонший розділ продукту).** R4 = **сира крива значень у часі**.
Крива благає про норму / зону / оцінку — і саме тут НЕ можна: показуємо **ЩО і КОЛИ**,
не судимо. Table-stakes (ринок закриває — Apple / DILA / MyChart, часто з автоданих) →
наздоганяємо; наш нюанс — **discoverability** (динаміка не захована, анти-Synevo) **+
без норм**. **Гібридна модель (CLAUDE фіча 4):** **Показник** (серія: назва + одиниця,
з довідника або свій) **1—N Вимірювання** ({дата, значення, опц. файл-джерело}). Показник
**завжди має ≥1 вимірювання** → «n=0 крива» не існує, найтонший стан = **n=1**.

## Екрани R4-flow

### Аналізи — список показників
- **Назва (sitemap):** `Аналізи — список показників` · `(R4)`.
- **Job (jtbd):** R4 (сц.7) — бачити показники профілю, кожен із **останнім значенням + датою**, і заходити в динаміку.
- **Місце у flow:** `list` — вхід із Записи→Аналізи (і борг: дашборд «остання динаміка»).
- **Реальні стани:** **База ✓** (показники: останнє значення · дата · крива-слот на кожному) · **Порожній ✓** (нема показників — R4 опційний, це норма + CTA «додати перше вимірювання») · **Завантаження ✓** (список із сервера) · **Помилка ✓** (збій завантаження → Повторити).
- **Discoverability (анти-Synevo, O19):** список організовано **ПО показнику (серія), не по PDF-результату** — динаміка **не захована**; крива = **1 тап зі списку**. Це структурна відповідь на ринковий провал (Synevo ~70% виходів через заховану динаміку).

### Показник — крива в часі  *(без норм / зон — межа продукту)*
- **Назва (sitemap):** `Показник — крива в часі (без норм / зон)` · `(R4)`.
- **Job (jtbd сц.7):** побачити **динаміку** показника, не окремі цифри.
- **Місце у flow:** `curve → n {скільки вимірювань?}`.
- **Реальні стани (не 4 шаблонні):**
  - **База / крива ✓ (n≥2)** — **сира намальована крива** (лінія + точки + вісь часу; від фази мови Ґ криву малюємо реально — форма ілюстративна в каркасі, реальні дані в продукті; це оновлює §0-«слот» для аналізів). Список несе **сиру міні-криву (спарклайн)** у кожному рядку, десктоп — **майстер-деталь** (список + крива праворуч). Діапазон **міс/6міс/рік** (зум-виджет — вибір вікна перегляду, **не оцінка**); тап на точку → **значення + дата + джерело** (прикріплений файл). Остання точка виділена **розміром**, не кольором-оцінкою.
  - **Одна точка ✓ (n=1 — визнаний борг динаміки)** — одна точка ≠ динаміка (sitemap чек-ліст): **точка + чесна нота «потрібен ще ≥1 запис, щоб побачити динаміку»** + CTA «додати вимірювання». **БЕЗ вигаданої лінії / прогнозу.** Це **змістовний стан**, не шаблонний empty.
  - **Порожній (n=0) —** : н/д — показник без вимірювань не існує (створюється разом із першим вимірюванням).
  - **Завантаження ✓ / Помилка ✓** — крива з сервера (спільний легкий патерн зі списком).

### Додати вимірювання
- **Назва (sitemap):** `Додати вимірювання` · `(R4)`.
- **Job:** R4 — внести {значення + дата + одиниця (+ файл)} до показника; автодоповнення показника.
- **Місце у flow:** `add → pick / ref → val → fileq → save`.
- **Реальні стани:** **База ✓** (форма: показник · значення · одиниця · дата · опц. файл) · **Помилка ✓** (збій збереження — durable, Повторити). *(Порожній / Завантаження — н/д для форми.)*
- **Under-flow — довідник показників (автодоповнення, НЕ екран):** поле «показник» = ввід з автодоповненням із довідника (**канонічна назва + синоніми**, напр. «цукор»→«глюкоза»); при виборі канонічного **одиниця підставляється авто**; **«свій параметр»** → назва + одиниця вручну (гібрид). Файл-джерело — опц. прикріплення (вимірювання ↔ Документ).

**Не окремі екрани:** довідник показників (службовий reference у «Додати вимірювання»); дашборд «остання динаміка» — ✅ **міні-слот кривої** в кластері «Останнє» (десктоп; закриває борг O19).

## Матриця R4 (свої стани — серія+вимірювання, крива без норм)

| Екран | База | Порожній | Завантаження | Помилка |
|---|:--:|:--:|:--:|:--:|
| Аналізи — список показників | ✓ | ✓ (нема показників) | ✓ | ✓ |
| Показник — крива в часі | ✓ (n≥2) | ✓¹ (n=1 — одна точка) | ✓ | ✓ |
| Додати вимірювання | ✓ | — | — | ✓ (save) |

¹ **n=1 — не шаблонний «порожній», а змістовний стан** «одна точка, потрібен ще запис» (визнаний борг динаміки; sitemap). n=0 не існує (показник = ≥1 вимірювання).
*Пропозиція на КРОК 2:* завантаження/помилка списку й кривої — **легкі спільні варіанти** (shell+спінер / смужка-помилка+Повторити), по представнику, не унікальні. Порожній список і n=1 — окремі, бо змістовні.

## «Можна X без як» + МЕЖА — назвав ЗАРАЗ (до верстки)

1. **КРИВА при n=1 — ✅ ВИЗНАЧЕНО:** одна точка ≠ динаміка (визнаний борг). Показуємо **точку + значення + дата + чесну ноту «потрібен ще ≥1 запис, щоб побачити динаміку»** + CTA «додати вимірювання». **БЕЗ вигаданої лінії, прогнозу чи екстраполяції.** Змістовний стан, не порожній.
2. **ДОВІДНИК показника — ✅ ВИЗНАЧЕНО (гібрид, under-flow не екран):** у «Додати вимірювання» поле показника = **автодоповнення з довідника** (канонічна назва + **синоніми**: «цукор»→«глюкоза», «Hb»→«гемоглобін»); вибір канонічного → **одиниця авто** (г/л, ммоль/л); **«свій параметр»** → назва + одиниця вручну. Довідник — **службовий reference** (seed), не користувацька сутність, не екран (sitemap).
3. **DISCOVERABILITY (O19) — ✅ ЧАСТКОВО (список) + ✅ ЗАКРИТО (дашборд):** ринковий провал конкурентів (Synevo ~70% виходів — динаміка захована за PDF-результатами). **Відповідь у скоупі R4:** список організовано **ПО показнику (серія), не по результату** → крива = **1 тап зі списку**, кожен показник несе останнє значення. **Дашборд «остання динаміка» — закрито:** у `dashboard.html` кластер «Останнє» несе сире останнє значення (тап → повна крива) + **міні-слот кривої на десктопі** (де є місце); слот-бокс за конвенцією §0 (реальний SVG кривої в каркасах не малюємо — ассет живе в `analysis-curve.html`), межа §4 — сира крива без норм/зон.
4. **МЕЖА — AVOID (НАЙКРИТИЧНІШЕ; кожна спокуса названа + підтверджено «не додаємо»):**
   - **референсні норми / діапазон «норма»** — ✗ (класична SaMD-інтерпретація);
   - **зони «в межах / поза межами»**, підсвітка «abnormal»-точок — ✗;
   - **кольори-оцінки** (зелене=добре / червоне=погано) — ✗ (у каркасах кольору й так нема §8, і в tokens **не з'явиться**);
   - **стрілки / іконки «краще / гірше»**, лінії-цілі (target line) — ✗;
   - **«відхилення»**, «поза нормою», «критично» — ✗;
   - **%-зміна / дельта як ВИСНОВОК** («+15%», «покращення на…») — ✗ (обчислений висновок = SaMD; користувач **бачить** підйом/спад кривої — це сирий факт, ми його **не підписуємо**);
   - **текстові вердикти** «покращується / погіршується / в нормі» — ✗.
   - **✅ Дозволено (сирий факт, не судження):** сире значення · дата · **сира крива** (повна / міні-слот) · тап-точка (значення+дата+джерело) · діапазон **міс/6міс/рік** (вибір вікна перегляду, не оцінка).
   Саме тут крива найсильніше спокушає стати діагностом — **не йдемо** (CLAUDE §4; той самий принцип, що R2 «неповна ≠ оцінка» / R3 «журнал ≠ статистика»).

- **Назва (sitemap):** `Візити — список / найближчі` · `(R4)`.
- **Job (jtbd сц.5):** бачити майбутні візити (щоб не пропустити) і минулі (з нотатками).
- **Місце у flow:** `list` — вхід із Записи→Візити (і дашборд «найближчий візит» → деталь).
- **Реальні стани:** **База ✓** (дві секції: **Попереду** + **Відбулися**) · **Порожній ✓** (нема візитів — норма + CTA «додати перший») · **Завантаження ✓** · **Помилка ✓** (Повторити).

### Візит — деталь
- **Назва (sitemap):** `Візит — деталь` · `(R4)`.
- **Job:** деталь одного візиту; майбутній — керувати нагадуванням/перенести; минулий — сирі нотатки/результат.
- **Місце у flow:** `detail → when {майбутній чи минулий?}`.
- **Реальні стани (вміст за статусом, НЕ 4 шаблонні):**
  - **Майбутній (попереду) ✓** — коли · де · тип · повторюваність · **нагадування-статус** (+ fallback R3) · дія **«Перенести»** · дія **«Позначити відбувся»** (перебіг → минулий).

- **Реальні стани:** **База ✓** (форма: тип · дата/час · повторюваність · нагадування) · **Помилка ✓** (збій збереження — durable). *(Порожній / Завантаження — н/д для форми.)*
- **Under-flow — нагадування (перевикористання R3, НЕ екран):** інлайн-fieldset у формі: увімк · **випередження** (за тиждень / за день / кастом) · тихі години; push недоступний → **fallback R3** (локальне/email + видимий статус). Дефолт випередження — **«за тиждень»** (планові — завчасно, сц.5).

## «Можна X без як» + МЕЖА — назвав ЗАРАЗ

1. **НАГАДУВАННЯ перед візитом — ✅ ВИЗНАЧЕНО (перевикористання R3, під-флоу + дефолт):** інлайн-fieldset у формі візиту (не окремий екран): увімк · **випередження** (за тиждень / за день / кастом — **дефолт «за тиждень»**, бо сц.5 = завчасно) · тихі години. Push недоступний → **fallback R3** (локальне/email + видимий статус «push вимкнено») — **той самий патерн**, не новий.
2. **ЗВ'ЯЗОК візит ↔ дашборд — ✅ ЗАКРИТО (одне джерело):** «найближчий візит» уже на **Дашборді** (кластер «Сьогодні», зверстано; зараз `href="#"`) = **той самий запис Візиту**, що в списку/деталі (як прийом R3 — одне джерело, кілька видів). **Закриваю дашборд-`#`:** веде на `visit-detail.html` (у КРОК 2 — правка `dashboard.html`).
3. **МИНУЛИЙ vs МАЙБУТНІЙ — ✅ ВИЗНАЧЕНО (структура, не стан):** список показує **обидва** у **двох секціях** («Попереду» / «Відбулися»), розрізняє полем `статус` (як «Активні / Історія» у Ліках). Майбутній = нагадування + «Перенести»; минулий = нотатки/результат. Перебіг майбутній→минулий = дія **«Позначити відбувся»** (додає нотатки). Це **структура списку + вміст деталі**, не 4-й lifecycle-стан.
4. **МЕЖА — AVOID:** візит **зберігає** що призначив/сказав лікар — **сирий запис нотаток**; Kartka **НЕ радить, не оцінює** (жодних «варто звернутись», «краще перенести», «пропущений візит — погано»). CLAUDE §4: продукт **пам'ятає** сказане лікарем, **не генерує** порад. Той самий принцип, що крива R4 (факт, не судження).
